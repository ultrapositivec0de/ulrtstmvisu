# [PROPOSAL v2] Ultra Steem Editor: Екосистема нового покоління для створення, кураторства та публікації контенту на Steem

---

## 1. Резюме та ретроспектива досягнень (Executive Summary)

**Ultra Steem Editor** пройшов шлях від концепту легкого помічника (v26.5) до високоефективної, автономної багатоплатформної екосистеми версії **v4.8.0**. 

Завдяки попередньому етапу розробки було реалізовано не лише 100% задекларованих цілей попередньої дорожньої карти, а й здійснено колосальний технологічний прорив:
*   **Стек нового покоління:** Повний перехід на **React 19 + TypeScript + Tailwind CSS v4**.
*   **Гібридний редактор (Markdown ⇄ WYSIWYG):** Безшовна двостороння математична синхронізація каретки та скролу, що унеможливлює втрату фокусу або даних.
*   **Багатопотоковий рушій (Web Workers):** Очищення та парсинг важкого контенту без блокування UI (стабільні 60 FPS).
*   **Криптографічний локальний сейф (Smart Vault):** Банківський захист ключів через Web Crypto API (**AES-GCM + PBKDF2**) з PIN-кодом, локальне сховище IndexedDB.
*   **Повноцінний клієнт читання та кураторства (Reader Mode):** Мультиголосування з вибором відсотка, автоматичне логування дій куратора, формування та експорт кураторських Markdown-звітів.
*   **Кросплатформеність:** Підтримка **Web PWA**, збірок **NeutralinoJS** та нативного оточення **Tauri v2 (Rust)**.

### Навіщо потрібен Proposal v2?
Застосунок вже працює і має потужну архітектуру. Проте, щоб перетворити його з «програми для ентузіастів» на **золотий стандарт для щоденного використання всією спільнотою Steem**, необхідний перехід від етапу створення бази до етапу **бездоганного користувацького досвіду (UX), надійності, оптимізації, інтелектуального інформування та готових дистрибутивів**.

Дана пропозиція фокусується на вдосконаленні наявного інструментарію, усуненні бар'єрів для новачків, додаванні критично важливих перевірок (Pre-flight checks) та підготовці офіційних релізів для кінцевих користувачів.

### 🟢 ЕТАП 1: Інтуїтивність, Онбординг та Система Інформування (User Guidance & UX)
*Мета: Зробити застосунок зрозумілим з першої секунди для будь-якого нового автора Steem.*

1. **Інтерактивний покроковий тур (Interactive Onboarding Guide):**
   * Впровадження візуальних підказок при першому запуску: «Як обрати режим редактора», «Де зберігаються чернетки», «Як налаштувати безпечний сейф для ключів», «Як вставити галерею».
   * Можливість у будь-який момент перезапустити гід через меню налаштувань.
2. **Система розумних сповіщень (Smart Toast & Status System):**
   * Заміна стандартних спливаючих вікон на інформативні тости із контекстними діями (наприклад: *«Чернетку автоматично збережено»*, *«Помилка зв'язку з нодою — перемкнено на запасну»*).
   * Індикатор стану блокчейн-з'єднання у статусному рядку (Latency/Ping ноди в реальному часі).
3. **Розумні підказки та контекстний помічник (Inline Hints):**
   * Пояснення специфіки розмітки Steem безпосередньо під час набору: підказки щодо правильного обтікання зображень `pull-left` / `pull-right`, центрування тексту `<center>`, синтаксису прихованих блоків.

---

### 🟡 ЕТАП 2: Pre-Flight Валідація, Безпека публікації та RC-контроль
*Мета: Повний захист автора від випадкових помилок, зриву публікацій та втрати ресурсів.*

1. **Pre-flight перевірка перед публікацією (Publication Inspector):**
   * **Resource Credits (RC) Checker:** Запит поточного рівня RC акаунта перед broadcast-транзакцією. Якщо ресурсу недостатньо — користувач отримує чітке попередження із зазначенням орієнтовного часу відновлення.
   * **Broken Links & Image Checker:** Локальна експрес-перевірка лінків на зображення та зовнішні ресурси. Попередження, якщо лінк не відкривається (запобігання "битим" картинкам у пості).
   * **Tag Validator:** Контроль обов'язкового першого тегу (категорії), заборона неприпустимих спецсимволів у тегах, перевірка ліміту в 8 тегів.
   * **Empty Title / Content Guard:** Інтелектуальний захист від публікації порожнього або тестового контенту.
2. **Автоматичний вибір та перемикання нод (Failover Node Engine):**
   * Якщо обрана RPC-нода повертає 502/504 або не відповідає протягом 3 секунд, застосунок прозоро для користувача повторює запит через резервні ноди зі списку (`api.steemit.com`, `steemapi.com` тощо).

---

### 🟡 ЕТАП 3: Оптимізація Медіа, Drag-and-Drop та Клієнтська Компресія
*Мета: Зробити роботу з фотографіями швидкою, економною для трафіку та безвідмовною.*

1. **Клієнтська обробка та компресія зображень (Image Optimizer):**
   * Автоматичне конвертування важких JPG/PNG у формат **WebP** безпосередньо у браузері перед відправкою на `steemitimages.com`.
   * Зменшення ваги файлів на 60–80% без видимої втрати якості, що прискорює завантаження у рази навіть на слабкому мобільному інтернеті.
   * Інструмент швидкого кадрування (Crop) та пропорційного масштабування фотографій.
2. **Повноцінний Drag-and-Drop контенту:**
   * Можливість перетягувати зображення з провідника або браузера безпосередньо в активне місце тексту (на позицію каретки курсора), з миттєвим створенням плейсхолдера завантаження та автозаміною на фінальний SteemitImages URL.
3. **Підтримка відеохостингів екосистеми (Video Embed Assist):**
   * Зручна вставка та візуальне оформлення відеоплеєрів для **3Speak** та YouTube за єдиним стандартом адаптивності.

### 🔵 ЕТАП 4: Поглиблення інструментів Куратора та Автора
*Мета: Розширення аналітичних та прикладних інструментів для спільнот.*

1. **Розширений розклад черги (Scheduled Publishing & Queue 2.0):**
   * Збереження черги з точними таймстемпами у локальній базі IndexedDB.
   * Підтримка відкладеного старту публікацій для десктопного застосунку (поки запущений застосунок — публікації виходять чітко за встановленим графіком).
2. **Вдосконалений модуль Curation Feed & Analytics:**
   * Фільтрація стрічки читання за мовами, спільнотами та авторами.
   * Розрахунок приблизної вартості апвоуту в доларах/STEEM на основі поточної Steem Power користувача.
   * Зручний імпорт списків для муту (Mute Lists) та списків авторів для пріоритетного моніторингу.
3. **Імпорт/Експорт чернеток у Markdown/Frontmatter:**
   * Підтримка стандарту метаданих YAML Frontmatter у завантажуваних `.md` файлах (збереження заголовка, тегів, бенефіціарів у заголовку файлу для синхронізації з Obsidian, Logseq чи іншими редакторами).

### 🟣 ЕТАП 5: Автоматизація збірок (CI/CD) та Офіційні Релізи
*Мета: Забезпечити кінцевих користувачів простими інсталяторами без необхідності відкривати консоль розробника.*

1. **Налаштування GitHub Actions CI/CD:**
   * Автоматична кроскомпіляція релізів при випуску нових тегів (Tauri та NeutralinoJS):
     * **Windows:** `.msi` / `.exe` інсталятор.
     * **Linux:** `.AppImage` та `.deb` пакети.
     * **Web:** Автоматичний деплой PWA на Cloudflare Pages / GitHub Pages.
2. **Мобільний пакет Android (TWA / APK):**
   * Створення Android-пакета через Trusted Web Activity для можливості встановлення як звичайного Android-додатка з окремою іконкою в меню.
3. **Механізм автоматичного оновлення (Auto-Updater):**
   * Вбудована перевірка наявності нових релізів у десктопних збірках з повідомленням автора про появу свіжої версії.

## 5. Чому підтримка цього проєкту вигідна блокчейну Steem?

1. **Готовий результат з першого дня:** Це не фінансування «ідеї на папері». Інвестори та свідки підтримують проєкт, який вже має понад 100 000 рядків перевіреного коду, працює у браузерах сотень авторів та має бездоганну репутацію.
2. **Зниження бар'єра входу для авторів:** Повна локалізація, розумні підказки та відсутність необхідності розбиратися зі складним HTML/Markdown залучать нових блогерів, які звикли до сучасних редакторів на зразок Medium, Notion чи Substack.
3. **Безпека екосистеми:** Завдяки локальному сейфу (Web Crypto AES-GCM) автори не ризикують втратити свої Posting Keys на сумнівних сторонніх сайтах.
4. **Незалежність (True Decentralization):** Застосунок не має централізованого бекенду. Навіть якщо будь-який веб-сайт перестане працювати, десктопна версія або локальний PWA продовжать взаємодіяти з блокчейном безпосередньо.
5. **Повна відкритість (Open-Source):** Код доступний для аудиту, форків та використання іншими розробниками Steem.
