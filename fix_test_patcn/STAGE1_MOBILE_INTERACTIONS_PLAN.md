## 1. Завдання 1: Звуковий супровід та швидкість реакції
### Проблема
Подія `click` на сенсорних пристроях спрацьовує лише після повного циклу `touchstart -> touchend -> click`, що спричиняє затримку звуку на 80-150 мс порівняно з тактильним дотиком. Для віртуальних клавіш введення це створює дисонанс.
### Рішення
1. У `useTypingSound.ts`: забезпечити підтримку виклику звуку на ранніх фазах взаємодії.
2. Для віртуальних кнопок та екранних клавіш прив'язати звуковий тригер до `onPointerDown` (із захистом від повторного виклику на `onClick`).
3. Використовувати AudioContext у підготовленому стані (`state === 'running'`) без створення нових контекстів на кожен дотик.

## 2. Завдання 4: Мобільний Reader - тогл кнопки налаштувань
### Проблема
У `ReaderMobileBottomBar.tsx` клік на кнопку «Налаштування» викликає `onSelectViewMode('settings')`. Якщо налаштування вже відкриті, повторний клік нічого не робить, змушуючи перемикатися на інші вкладки.
### Рішення
Зробити кнопку двопозиційним перемикачем (тоглом):
```tsx
onClick={() => {
  if (viewMode === 'settings') {
    onSelectViewMode(previousViewMode || 'feed');
  } else {
    onSelectViewMode('settings');
  }
}}
```

## 3. Завдання 5: Стабільність хедера при відкритті клавіатури
### Проблема
У `Header.tsx` кнопка налаштувань має умову `showMobileBottomBar ? "hidden" : "flex"`.
Коли на смартфоні відкривається клавіатура, `visualViewport` зменшується, `showMobileBottomBar` переходить у `false` (приховується, щоб не перекривати екран), і кнопка налаштувань раптово з'являється у верхньому хедері, виштовхуючи кнопку публікації (ракету) за межі видимого екрана.
### Рішення
Врахувати `isMobileLayout`: якщо пристрій мобільний, кнопка налаштувань не повинна несподівано з'являтися у хедері лише тому, що клавіатура тимчасово приховала нижню панель:
`className={clsx((isMobileLayout || showMobileBottomBar) ? "hidden" : "flex", ...)}`
Додатково зафіксувати пріоритет відображення кнопки публікації (`shrink-0`).

## 4. Завдання 6: Фокус та віджет меню
### Проблема
Клік на перемикачі положення віджета або елементи меню перехоплює фокус або навпаки повертає фокус у приховане поле редактора, викликаючи мимовільне відкриття/закриття екранної клавіатури.
### Рішення
1. Для кнопок керування панелями віджета додати `onPointerDown={(e) => e.preventDefault()}` де необхідно запобігти крадіжці фокусу від тексту.
2. При явному виборі модальних вікон чи дій викликати `activeElement?.blur()` для акуратного приховування клавіатури на сенсорних пристроях.

## 5. Завдання 7: Віджет Drag-Reorder та скрол на дотик
### Проблема
У `TamedWidget.tsx` весь блок або рядок елемента списку має активний drag-listener. На мобільних браузерах це блокує нативний вертикальний жест скролу сторінки.
### Рішення
1. Використовувати Framer Motion `useDragControls()`.
2. Встановити `dragListener={false}` на сам контейнер рядка.
3. Додати виділену іконку-рукоятку (`GripVertical`), на якій підключено `onPointerDown={(e) => dragControls.start(e)}`.
4. Встановити на весь контейнер властивість `touch-action: pan-y`.
