# Архітектурний план Етапу 5: Процедурний звуковий синтез друку (Zero-GC, Android/Desktop)

> **Файл документа:** `/fix_test_patcn/STAGE_5_AUDIO_SYNTH_PLAN.md`  
> **Мета:** Створення надшвидкого, енергоефективного та гармонійного процедурного аудіо-рушія друку без затримок (0 мс), без навантаження на Garbage Collector (Zero-GC), із повною підтримкою нативних додатків Android/Tauri та фізичних/віртуальних клавіатур.

## 1. Порівняльний аналіз архітектурних рішень

| Критерій | Старий підхід (On-the-fly allocation) | Підхід з консультації (AudioWorklet) | **Наш оптимізований підхід (Fast-Path Native Voice Pool)** |
| :--- | :--- | :--- | :--- |
| **Виділення пам'яті** | ❌ Створення 5–10 нових вузлів на кожен символ, `setTimeout(disconnect)` | ⚠️ Постійний обмін `postMessage` між потоками, створення структур |  **Zero-GC:** Фіксований пул із 8–12 готових голосів із рециркуляцією |
| **Навантаження на CPU** | ❌ Високе навантаження на Garbage Collector (фризи на Android) | ⚠️ Додаткові витрати на JS DSP у ворклеті (посемплерні цикли) |  **Мінімальне:** Нативні C++ ноди Web Audio + розрахунки за таблицями LUT за $O(1)$ |
| **Сумісність з Android WebView / Tauri** | ⚠️ Працює, але троттлить при швидкому наборі | ❌ Ризик блокування CSP (`Blob URL` / `file://` протоколи) |  **100% нативна сумісність** з усіма WebView, iOS Safari, Android, Chrome, Firefox |
| **Генерація випадкових чисел (Шум/Механіка)** | ❌ `Math.random()` у циклах (повільно) |  Швидкий бітовий `Xorshift32` |  **Xorshift32 PRNG** + попередньо виділені циклічні буфери шуму (`AudioBuffer`) |
| **Запобігання клікам / тріску** | ❌ Різкі спади, клацання при накладанні |  М'який Release (2–3 мс) |  **Anti-Click Voice Stealing** (експоненційний спад 3–4 мс) + **Master Soft-Limiter** |
| **Зв'язок з React** | ❌ Залежність від ре-рендерів стану |  Повна ізоляція |  **Ізольований Singleton (0 мс)**. Zustand використовується **лише** для налаштувань UI |

## 2. Детальна схема потоку даних (Pipeline)

```
[ Подія вводу: DOM / beforeinput / keydown ]
                   │
                   ▼ (миттєвий синхронний виклик, без виклику setState / React-рендера)
[ Input Router & Context Resolver (KeyHashDispatcher) ]
  ├── Визначає: символ, inputType, Shift, активну мову, ряд клавіатури
  ├── Android Fallback: якщо keydown.code === 229 / Unidentified ──► очікує і бере точний символ із beforeinput (e.data)
  ├── Дедуплікація CompositionEvent (запобігання подвійним звукам при Т9 / автопідказках)
  └── Без штучних блокуючих debounce таймерів (точний відгук для швидкостей 100+ слів/хв)
                   │
                   ▼
[ SoundEngine Core (Vanilla TS Singleton) ]
  ├── Завантажує активний SoundPreset (Merge з дефолтними значеннями)
  ├── Розрахунок висоти ноти за $O(1)$:
  │    ├── Швидкий бітовий хеш: (h = (h << 5) - h + charCode) | 0
  │    ├── Готова таблиця частот (Precomputed Frequency LUT Float32Array)
  │    └── Прив'язка до гармонійної сітки (Пентатоніка / Мажор / Мінор / Карильйон)
  └── Lookahead-планування часу (Math.max(audioCtx.currentTime, targetTime))
                   │
                   ▼
[ Voice Pool Manager (8–12 фіксованих голосів) ]
  ├── 1. Пошук вільного голосу (state === 'idle')
  ├── 2. Якщо всі зайняті: Voice Stealing найстарішого голосу з мікро-спадом 3–4 мс (Anti-Click)
  ├── 3. Запуск синтезу (Осцилятор + Свайп фільтра + Xorshift-шум)
  └── 4. Вихід у Master Dynamics Compressor (запобігання перевантаженню при акордах)
                   │
                   ▼
[ Системний аудіо-рушій ОС (AAudio / WASAPI / CoreAudio) ]
```

## 3. Ключові оптимізації та технічні деталі

### 3.1. Швидкий генератор псевдовипадкового шуму (Xorshift32 PRNG)
Замість повільного стандартного `Math.random()` використовується швидка 32-бітна бітова генерація:
```ts
let xorState = 0x12345678;
function xorshift32(): number {
  xorState ^= xorState << 13;
  xorState ^= xorState >> 17;
  xorState ^= xorState << 5;
  return (xorState >>> 0) / 4294967296; // Швидке число в діапазоні [0, 1)
}
```
Також при першому старті один раз генеруються невеликі циклічні `AudioBuffer` (0.25 сек) білого, рожевого та коричневого шуму.

### 3.2. Таблиці попередньо розрахованих частот (Frequency Lookup Tables - LUT)
Замість математичних розрахунків `440 * Math.pow(2, (note - 69) / 12)` під час кожного натискання, масив усіх 128 MIDI-нот та специфічних шкал генерується **один раз під час завантаження програми** у типізований `Float32Array`. Вибірка частоти виконується миттєво за $O(1)$.

### 3.3. Надійне розблокування Autoplay Policy на Android та Desktop
- Перший же клік чи тач користувача у будь-якому місці інтерфейсу (`pointerdown`, `touchstart`) виконує `AudioContextManager.unlockAudio()`.
- Якщо звуки вимкнені в налаштуваннях — контекст автоматично засинає (`ctx.suspend()`), зберігаючи 100% заряду батареї.

### 3.4. Розумна обробка мобільних клавіатур на Android
- Мобільні клавіатури (Gboard, Samsung Keyboard) часто надсилають `keydown` із кодом `229` або `'Unidentified'`.
- Алгоритм перехоплює подію `beforeinput`, отримує точний введений символ через `e.data`, або тип операції (`deleteContentBackward`, `insertLineBreak`), миттєво відтворюючи відповідний тембр.
