## 1. Завдання 3: Вивантаження зображень через Steem Vault (підпис Posting Key)
### Діагностика проблеми
- Через розширення Steem Keychain вивантаження працює, оскільки Keychain приймає готовий буфер та генерує префікс повідомлення `ImageSigningChallenge` за власним протоколом.
- При використанні власного сховища (Vault) `SecurityService.signBuffer` підписує хеш буфера напряму або використовує інший бінарний формат підпису ECDSA (`secp256k1`), який SteemitImages API відхиляє з помилкою 400/403.
### План вирішення
1. Порівняти точний протокол SteemitImages:
   - Формат челенджу: `ImageSigningChallenge` + `Buffer.concat([prefix, fileBuffer])` або `sha256(prefix + buffer)`.
   - Формат підпису у заголовках: `signature` у шістнадцятковому або компактному 65-байтовому форматі (включаючи `recovery id` `v`).
2. Додати діагностичний тест у `./fix_test_patcn/test_vault_image_signing.ts` для емуляції підпису та звірки з еталоном SteemitImages.
3. Оновити виклик підпису в `useSteemGallery.ts` виключно для гілки Vault, **не торкаючись** працюючої гілки Keychain.

## 2. Завдання 9: Повноекранний лайтбокс зображень та перехоплення лінків
### Проблема
У дописах Steem зображення часто загорнуті у посилання Markdown: `[![alt](url)](target_url)`.
При кліку на картинку браузер намагається відкрити зовнішній сайт `target_url` або нову вкладку, замість зручного перегляду зображення.
### План вирішення
1. Створити легкий компонент лайтбоксу: `src/components/common/ImageLightboxModal.tsx` з підтримкою:
   - Відкриття в повноекранному режимі з темним напівпрозорим фоном (`--modal-bg` / `backdrop-blur`).
   - Кнопки закриття («Х» або «Назад до допису»).
   - Масштабування (коліщатко миші або жест pinch-to-zoom на сенсорних екранах).
2. У `ReaderContent.tsx` та в режимі попереднього перегляду редактора:
   - Додати делегування кліків на рівні контейнера контенту:
   ```tsx
   const handleContentClick = (e: React.MouseEvent) => {
     const target = e.target as HTMLElement;
     if (target.tagName === 'IMG') {
       e.preventDefault();
       e.stopPropagation();
       setSelectedImageSrc((target as HTMLImageElement).src);
     }
   };
   ```
   - Завдяки `e.preventDefault()` та `e.stopPropagation()` батьківський тег `<a>` не спрацьовує, користувач залишається в додатку та насолоджується якісним переглядом.
