# План усунення проблем з меню генерації звуків та небажаним викликом віртуальної клавіатури

Цей документ містить детальний технічний аналіз виявлених проблем та покроковий план їх безпечного усунення без побічних наслідків для редактора та верстки.

---

## Частина 1. Аналіз першопричин (Root Cause Analysis)

### Проблема 1: Контейнер кнопки звуку (`AudioControlWidget`) зміщується вправо/вліво при активації
**Де виникає:** `src/components/audio/AudioControlWidget.tsx` (рядки 66–93).
**Причина:**
1. Коли звук увімкнено (`enabled === true`), всередині кнопки миттєво додається індикатор-крапка (`<span className="w-1.5 h-1.5 rounded-full ...">`), а коли вимкнено — цей DOM-елемент повністю зникає (`{enabled && ...}`). Це змінює фізичну ширину кнопки на ~10px (`6px` ширина + `4px` gap) при кожному перемиканні.
2. На екранах `md+` текст кнопки змінюється між коротким `'Звук'` та назвою активного пресета (`activePreset.name.split(' ')[0]`, наприклад `'Typewriter'`, `'Mechanical'`, `'Bubble'`), що також змінює ширину кнопки та зсуває сусідні елементи й відкрите випадаюче меню.
3. Оскільки кнопка розташована у flex-контейнері з вирівнюванням праворуч, будь-яка зміна її ширини візуально зміщує і саму кнопку, і прив'язане до неї спливаюче меню.

---

### Проблема 2: Випадаюче меню звуку (`AudioControlWidget`) у портретному режимі вилазить за правий край екрана
**Де виникає:** `src/components/audio/AudioControlWidget.tsx` (рядок 129) та аналогічно меню інтервалів у `src/components/editor/EditorPane.tsx` (рядок 614).
**Причина:**
Поточний клас позиціонування поповера:
```tsx
className="absolute left-0 sm:left-auto sm:right-0 top-full mt-2 w-72 max-w-[calc(100vw-1rem)] ..."
```
На мобільних екранах у портретному режимі (`< 640px`, тобто до брейкпоінта `sm:`) діє правило `left-0` відносно контейнера кнопки `AudioControlWidget`.
Проте сам `AudioControlWidget` знаходиться **у правій частині панелі режиму редактора** (поруч із кнопкою інтервалів, з-під правого краю екрана на відстані ~45–60px).
Коли меню шириною `w-72` (`288px`) прив'язується своїм **лівим краєм (`left-0`)** до кнопки, розташованої майже біля правого краю екрана (наприклад, на координаті `X = 310px` при ширині екрана `375px`), воно простягається від `310px` до `598px` — тобто **на ~220px виходить за межі правого краю екрана**!
Навіть якщо замінити `left-0` на `right-0`, кнопка не стоїть впритул до самого правого краю (праворуч від неї ще є кнопка `Spacing`), або на вузьких екранах (`320px–360px`) `absolute` відносно проміжної кнопки може впиратися в лівий або правий край.

### Проблема 3: Раптовий виклик / пересмикування віртуальної клавіатури під час зміни налаштувань (зокрема вибору режиму плаваючого віджета «Внизу» тощо)
**Де виникає:**
1. **Головний винуватець — реактивний `useEffect` у `src/hooks/useEditorModeManager.ts` (рядки 474–504):**
```tsx
  useEffect(() => {
    if (activeView === 'editor' && activeMobileTab === 'editor') {
      if (isTransitioningModeRef.current) return;
      setTimeout(() => {
        if (isTransitioningModeRef.current) return;
        if (editorMode === 'visual') {
          restoreVisualSelection();
        } else {
          restoreMarkdownCursorAndScroll();
        }
        isSyncingRef.current = false;
      }, 150);
    } else { ... }
  }, [
    activeView,
    activeMobileTab,
    editorMode,
    saveCursorPosition,
    restoreVisualSelection,
    saveVisualSelection,
    restoreMarkdownCursorAndScroll,
    isKeyboardOpen,     // <--- ТРИГЕР 1!
    widgetPos,          // <--- ТРИГЕР 2!
    toolbarIconSize,    // <--- ТРИГЕР 3!
    editorRef,
    isSyncingRef
  ]);
```
**Що відбувається покроково:**
- Користувач відкриває **Налаштування (`SettingsModal`)** або **меню шестерні віджета (`TamedWidget`)** і змінює:
  - Режим плаваючого віджета (`widgetPos`: наприклад, обирає `Внизу` / `bottom` або `Плаваючий`), АБО
  - Розмір іконок панелі (`toolbarIconSize`), АБО
  - Закриває віртуальну клавіатуру (`isKeyboardOpen` змінюється з `true` на `false`).
- Оскільки `widgetPos`, `toolbarIconSize` та `isKeyboardOpen` включені у масив залежностей цього `useEffect` (а також у залежності `restoreMarkdownCursorAndScroll` -> `restoreVisualSelection` -> `scrollCaretIntoView`), **кожна зміна цих параметрів у налаштуваннях запускає таймер на 150 мс**, який примусово викликає `restoreVisualSelection()` або `restoreMarkdownCursorAndScroll()`.
- Усередині `restoreVisualSelection()` (`src/hooks/useWysiwygSync.ts`, рядок 523) виконується:
  ```tsx
  if (document.activeElement !== wysiwygRef.current) {
    wysiwygRef.current.focus({ preventScroll: true });
  }
  ```
  А всередині `restoreMarkdownCursorAndScroll()` (`src/hooks/useEditorModeManager.ts`, рядок 177) виконується:
  ```tsx
  ta.focus({ preventScroll: true });
  ```
- **Наслідок:** Навіть коли відкрите модальне вікно `SettingsModal`, або відкрите меню налаштувань віджета `isWidgetMenuOpen`, або користувач просто згорнув клавіатуру на мобільному — через 150 мс скрипт **примусово повертає фокус у `textarea` або `contentEditable` редактора**, що на Android / iOS миттєво викликає віртуальну клавіатуру просто поверх відкритих налаштувань або спричиняє її «пересмикування» (закрилася -> через 150 мс знову виїхала)!

2. **Другий чинник — перехоплення фокуса при взаємодії з контролами (`onMouseDown={(e) => e.preventDefault()}` та відсутність `blur` редактора при відкритті модальних вікон і поповерів налаштувань):**
- У `SettingsModal.tsx` (рядок 372) та `TamedWidget.tsx` (рядок 439) кнопки перемикання `widgetPos` мають `onMouseDown={(e) => e.preventDefault()}`. Якщо перед відкриттям меню редактор мав фокус (або отримав його), `preventDefault()` не дає браузеру зняти фокус з редактора.
- При відкритті будь-якого модального вікна (`activeModal !== null`, `isAudioPresetsModalOpen`, `isSMenuOpen`) або меню налаштувань (`isWidgetMenuOpen`, `isSpacingMenuOpen`, `AudioControlWidget` `isOpen`), якщо редактор залишався у фокусі, будь-яка перерахунок layout/viewport може повторно підняти клавіатуру.

## Частина 2. Покроковий план безпечного виправлення

### Крок 1. Стабілізація кнопки та позиціонування випадаючого меню звуку (`AudioControlWidget.tsx`) і сусіднього меню інтервалів (`EditorPane.tsx`)
1. **Фіксація геометрії тригера `AudioControlWidget`:**
   - Залишити індикатор-крапку в DOM постійно (змінювати лише прозорість/колір `opacity-100` / `opacity-30 bg-slate-500`), щоб увімкнення/вимкнення звуку не змінювало ширину кнопки ні на піксель.
   - На мобільних і планшетних екранах уніфікувати підпис кнопки або задати стабільну ширину, щоб кнопка не «стрибала» праворуч/ліворуч.
2. **Виправлення позиціонування спливаючого вікна звуку в портретному та мобільному режимі:**
   - На мобільних екранах (`< 640px`, портретний режим) замінити `absolute left-0` на вирівнювання, яке гарантовано вписується у межі екрана:
     - Використати позиціонування відносно правого краю (`right-0`) або адаптивне фіксоване/центроване вікно на вузьких портретних екранах (`max-sm:fixed max-sm:left-2 max-sm:right-2 max-sm:top-[calc(var(--header-height,3.5rem)+4.75rem+env(safe-area-inset-top,0px))] max-sm:w-auto max-sm:max-w-[calc(100vw-1rem)] max-sm:mx-auto sm:absolute sm:right-0 sm:left-auto sm:top-full sm:mt-2 sm:w-72`), аналогічно до того, як це реалізовано для мобільних меню у `Header.tsx`.
     - Це 100% гарантує, що у портретному режимі меню ніколи не вилізе за правий чи лівий край екрана, буде повністю видимим і не залежатиме від зміщення кнопки.
   - Аналогічно перевірити та захистити сусіднє спливаюче меню `isSpacingMenuOpen` у `EditorPane.tsx` (`max-w-[calc(100vw-1rem)]`), щоб обидва меню у цій панелі поводилися однаково стабільно.

---

### Крок 2. Усунення хибного авто-фокусу редактора в `useEditorModeManager.ts` та `useWysiwygSync.ts`
1. **Очищення залежностей `useEffect` у `src/hooks/useEditorModeManager.ts` (рядки 474–504):**
   - Цей `useEffect` призначений **виключно** для відновлення позиції курсора при перемиканні вкладки `activeView` (`reader` <-> `editor`) або мобільної вкладки `activeMobileTab` (`preview` <-> `editor`).
   - Видалити `isKeyboardOpen`, `widgetPos`, `toolbarIconSize` з масиву залежностей цього ефекту (використовуючи актуальні функції через ref або стабільні колбеки), щоб:
     - зміна `widgetPos` («Внизу», «Плаваючий», «Вимкнено»);
     - зміна `toolbarIconSize`;
     - відкриття/закриття віртуальної клавіатури (`isKeyboardOpen`)
     **більше ніколи не запускали примусовий `.focus()` на редакторі!**
2. **Захист `restoreVisualSelection` та `restoreMarkdownCursorAndScroll` від виклику під час відкритих модалок або меню налаштувань:**
   - Передати прапорець або перевірку активних оверлеїв (або перевіряти, чи не відкрито модальне вікно / поповер налаштувань), і не викликати `.focus()` на `editorRef` / `wysiwygRef`, якщо користувач зараз не взаємодіє з редактором напряму (наприклад, коли відкрито `activeModal`, `isAudioPresetsModalOpen`, `isWidgetMenuOpen`, `isSpacingMenuOpen`).
   - Додати опціональний параметр `shouldFocus = true` у `restoreVisualSelection` та `restoreMarkdownCursorAndScroll`, щоб за потреби відновлювати позицію без агресивного виклику клавіатури на мобільних пристроях при фонових переходах.

---

### Крок 3. Захист модальних вікон та панелей налаштувань від паразитного фокусу клавіатури
1. **Автоматичний `blur` редактора при відкритті модальних вікон і меню налаштувань:**
   - У `BaseModal.tsx` при монтуванні/відкритті модального вікна (`isOpen === true`), якщо `document.activeElement` є редактором (`#main-editor` або `.wysiwyg-editor`), виконувати безпечний `blur()`, щоб віртуальна клавіатура гарантовано ховалася при відкритті Налаштувань та не перекривала інтерфейс.
   - У `TamedWidget.tsx` при відкритті меню налаштувань самого віджета (`setIsWidgetMenuOpen(true)`), а також у `AudioControlWidget.tsx` та `isSpacingMenuOpen` на мобільних пристроях: не дозволяти редактору утримувати чи перехоплювати фокус під час зміни повзунків (`<input type="range">`), чекбоксів та кнопок режимів (`Внизу` / `Плаваючий` / `Вимкнено`).
2. **Прибирання зайвого `onMouseDown={(e) => e.preventDefault()}` у `SettingsModal.tsx`:**
   - У `SettingsModal.tsx` (рядок 372) кнопка вибору `widgetPos` не повинна утримувати фокус редактора через `preventDefault()`, оскільки користувач знаходиться у модальному вікні налаштувань.

---

### Крок 4. Перевірка та валідація
1. Перевірка компіляції TypeScript (`compile_applet`) та лінтера (`lint_applet`).
2. Перевірка всіх сценаріїв:
   - Відкриття меню звуків у портретному режимі (320px, 375px, 414px) та перемикання тумблера звуку й пресетів — відсутність зміщення кнопки та повне входження меню в екран.
   - Зміна режиму плаваючого віджета («Внизу», «Плаваючий», «Вимкнено») як у `SettingsModal`, так і в меню шестерні `TamedWidget` — віртуальна клавіатура не виїжджає і не пересмикується.
   - Зміна повзунків розміру шрифту, іконок, інтервалів, прозорості віджета та гучності звуку — клавіатура залишається закритою.
   - Форматування тексту кнопками панелі інструментів у режимах Visual та Markdown — працює штатно зі збереженням виділення.
