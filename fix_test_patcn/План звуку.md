# План реалізації: Модуль процедурного аудіо-відгуку клавіатури (Audio Typing Synth)

> **Статус:** Схвалення архітектури та підготовка до покрокового впровадження  
> **Технологічний стек:** Чистий Web Audio API (без сторонніх важких бібліотек, без зовнішніх аудіосемплів mp3/wav, повна автономність, підтримка WebView/WebKit/Tauri/Neutralino).  
> **Усталений стан:** **Вимкнено (`enabled: false`)** для збереження тиші та автономності батареї.

---

## 1. Архітектурні принципи та оптимізація ресурсів

### 1.1. Zero-Garbage Collection & Рециркуляція аудіо-вузлів (Node Pooling)
* **Проблема:** При швидкому наборі тексту (300–600 знаків/хв) виклик `new AudioContext()` або постійне створення `ctx.createOscillator()` / `ctx.createGain()` призводить до переповнення оперативної пам'яті та частих пауз Garbage Collector (фризи інтерфейсу).
* **Рішення:**
  - Використання **єдиного Singleton `AudioContext`**, який створюється **ліниво (lazy initialization)** лише після першої явної взаємодії користувача з увімкненою опцією (відповідно до вимог браузерної політики `Autoplay Policy`).
  - **Фіксований пул голосів синтезу (Polyphony Voice Pool):** Пул з 6–8 заздалегідь підготовлених або швидко перепідключаємих ланцюжків синтезу. Коли користувач натискає наступну клавішу, береться наступний вільний або найстаріший активний голос (Round-robin voice stealing).
  - Короткотривалі огинаючі (decay 20–80мс) з плавним спадом до нуля через `exponentialRampToValueAtTime`, що запобігає артефактам "клацання" (audio clicks/pops).

### 1.2. Автоматичний сон та збереження енергії (Auto-suspend / Auto-resume)
* Якщо після останнього натискання клавіші минуло більше 4 секунд, модуль викликає `audioCtx.suspend()`, переводячи аудіо-драйвер браузера в режим нульового енергоспоживання.
* При новому натисканні клавіші чи тач-введенні виконується швидкий `audioCtx.resume()` без затримок.
* При вимкненні звуку в налаштуваннях або на панелі — контекст миттєво глушиться та звільняє аудіо-канал системи.

## 2. Структура файлів модулю

```

└── services/
    └── audio/
        ├── index.ts                      # Експорт публічного API
        ├── AudioContextManager.ts        # Singleton контексту, сон/пробудження, обробка блокувань браузера

        ├── presets/

        │   └── presetSchema.json         # JSON-схема валідації зовнішніх пресетів
        └── hooks/

```

## 3. Двоканальне перехоплення введення: Фізична + Віртуальна Touch-клавіатура

### 3.1. Фізична клавіатура (Desktop / Ноутбуки)
* Прослуховування подій `keydown` на контейнері редактора (або глобально з фільтрацією фокусу).
* Аналіз властивостей:
  - `event.code`: `KeyA` ... `KeyZ`, `Digit0` ... `Digit9`, `Space`, `Enter`, `Backspace`, `Delete`, `Tab`, `Escape`.
  - `event.key`: безпосередній введений символ з урахуванням активної розкладки (кирилиця, латиниця, спецсимволи).
  - Спеціальні функціональні клавіші (`Backspace` — звук видалення/повернення каретки, `Enter` — звук переведення рядка друкарської машинки, `Space` — глухий пробіл).

### 3.2. Віртуальна тач-клавіатура смартфонів (Mobile / Tablet / IME)
* **Проблема віртуальних клавіатур на смартфонах:** Мобільні клавіатури (Gboard, iOS Safari Keyboard) не завжди генерують повноцінні коди клавіш у `keydown` (часто повертають `keyCode: 229` або пустий `event.key`).
* **Рішення:**
  - Обробка стандартизованої події **`beforeinput` / `input`**:
    - `e.inputType === 'insertText'` -> синтез звуку звичайної літери на основі `e.data`.
    - `e.inputType === 'deleteContentBackward'` або `deleteContentForward'` -> звук Backspace.
    - `e.inputType === 'insertLineBreak'` або `'insertParagraph'` -> звук Enter.
    - `e.inputType === 'insertCompositionText'` -> безпечна обробка автовиправлень/T9.
  - Окремий тач-відгук при натисканні на екранні кнопки панелі форматування (жирний, курсив, заголовки, списки тощо).

## 4. Алгоритм унікального відгуку для кожної клавіші (Key-Hash Pitch & Resonance Modulation)

Кожна літера, символ та мова повинні звучати індивідуально, як різні механічні літероносії або різні віртуальні струни:

1. **Базова частота клавіші:** Обчислюється детермінований 32-бітний хеш із рядка `key` + `code` + `locale/script`:
   ```ts
   // Приклад алгоритму швидкого хешування
   function getKeyHash(char: string, code: string): number {
     const str = char || code;
     let hash = 0;
     for (let i = 0; i < str.length; i++) {
       hash = ((hash << 5) - hash) + str.charCodeAt(i);
       hash |= 0;
     }
     return Math.abs(hash);
   }
   ```
2. **Модуляція висоти звуку (Pitch Shifter):**
   - На основі хешу розраховується зсув частоти: `deltaPitch = ((hash % 100) / 100 - 0.5) * preset.pitchVariance`.
   - Кирилиця (`ж`, `ї`, `щ`) матиме власний характерний спектральний відтінок, відмінний від латиниці (`j`, `q`, `w`).
   - Спецсимволи (`!`, `@`, `#`, `$`, `%`) отримують додатковий високочастотний резонанс фільтра.
3. **Функціональні групи:**
   - **Spacebar:** Знижена частота (глибокий бас), трохи довший сустейн, більше шуму низьких частот (демпфер пробілу).
   - **Enter / Return:** Двотональний удар (механічний клац + відлуння дзвоника каретки).
   - **Backspace / Delete:** Більш різкий, сухий, глухий "stop-click".

## 5. Вшиті пресети та відкритий шаблон для користувацьких файлів

### 5.1. Початковий набір вшитих стилів:
1. **Mechanical Cherry MX Blue:** Яскравий подвійний клік (пластиковий контакт + пружинний клац).
2. **Vintage Typewriter (Ундервуд):** Масивний металевий удар молоточка об папір з коротким резонансом каретки.
3. **Lubed Linear / Deep Thock:** Глибокий, глухий, оксамитовий звук для комфортного нічного набору.
4. **Cyber Neon / Sci-Fi Synth:** Тонкі короткі синусоїдальні пінги з легким частотним спадом (стиль ретро-футуризму).
5. **Water Bubble Drop:** Делікатні краплі води, м'які для слуху, ідеальні для зосередженої роботи без втоми.
6. **Soft Membrane / Office Minimal:** Майже непомітний ледь чутний клік високої чіткості.

### 5.2. Шаблон структури пресету (JSON / TypeScript-інтерфейс)
Користувачі зможуть створити файл, наприклад `my-custom-synth.json`, або згенерувати його за допомогою штучного інтелекту:

```json
{
  "$schema": "https://steemeditor.app/schemas/sound-preset.v1.json",
  "id": "vintage-typewriter-heavy",
  "name": "Heavy Vintage Typewriter",
  "description": "Потужний металевий відгук із шумом удару по стрічці",
  "author": "Community",
  "version": "1.0.0",
  "tags": ["mechanical", "retro", "heavy"],
  "oscillator": {
    "type": "triangle",
    "baseFreq": 280,
    "freqDecay": 0.04,
    "pitchVariance": 60
  },
  "noise": {
    "type": "pink",
    "gain": 0.35,
    "durationMs": 35
  },
  "filter": {
    "type": "bandpass",
    "baseFrequency": 1200,
    "q": 3.5
  },
  "envelope": {
    "attack": 0.002,
    "decay": 0.05,
    "sustain": 0.0,
    "release": 0.02
  },
  "specialKeys": {
    "space": { "pitchMultiplier": 0.65, "gainMultiplier": 1.2 },
    "enter": { "pitchMultiplier": 1.4, "extraBell": true },
    "backspace": { "pitchMultiplier": 0.85, "noiseGain": 0.5 }
  }
}
```

### 5.3. Механізм додавання зовнішніх пресетів:
- **Локальний імпорт файлів (File Picker / Drag-and-Drop):** Користувач може обрати `.json` файл зі свого пристрою (чи папки на диску).
- **Синхронізація у локальне сховище (IndexedDB / localStorage):** Завантажені пресети зберігаються локально між сесіями без відправки на сервер.
- **Вбудований валідатор схеми:** Перевірка безпеки (чи всі параметри чисельні, відсутність ін'єкцій шкідливого коду).

## 6. Інтерфейс користувача (UI / UX)

### 6.1. Кнопка швидкого доступу в хедері (Header)
* Розміщення: у правому блоці дій хедера поруч з перемикачем теми, режимами та синхронізацією.
* **Іконка:** Динамік / Навушники (`Volume2` коли увімкнено, `VolumeX` коли вимкнено).
* **Поведінка по кліку:** 
  - Простий клік (або тач) — миттєве перемикання **Вкл / Викл** (із візуальною індикацією стану).
  - Довгий клік (або клік на стрілочку випадаючого меню) — відкриває **швидке міні-меню налаштувань**:
    1. Повзунок гучності (Volume Slider 0–100%).
    2. Швидкий селектор пресету (зі списком останніх використаних та обраних).
    3. Кнопка "Усі пресети / Менеджер".

### 6.2. Модальне вікно / Панель «Менеджер звуків»
* Організовано за категоріями: **«Обрані ⭐»**, **«Вшиті»**, **«Користувацькі»**.
* Кнопка **«Послухати» (Preview)** біля кожного пресету без необхідності друкувати.
* Кнопка зірочки **⭐ (В обране)** для швидкого фільтрування найкращих звуків.
* Кнопка **«Імпортувати пресет (.json)»** та кнопка **«Експортувати шаблон»**.
* Попередній перегляд і налаштування індивідуального балансу (Tone, Resonance, Randomness).

## 7. Збереження стану та персистентність
* Усі параметри зберігаються в `localStorage` під ключем `steem_editor_audio_synth_config`:
  ```ts
  interface AudioTypingSettings {
    enabled: boolean;            // default: false
    activePresetId: string;      // default: "cherry-blue"
    volume: number;              // default: 0.5 (50%)
    favoritePresetIds: string[]; // default: ["cherry-blue", "vintage-typewriter"]
    customPresets: SoundPreset[];
  }
  ```
* Жодне оновлення вкладки чи браузера не скидає обрані налаштування користувача.

## 8. Покроковий план впровадження (етапи)

1. **Етап 1: Базовий звуковий сервіс (Core Synth)**
   - Створення `src/services/audio/AudioContextManager.ts` та `SoundSynthEngine.ts`.
   - Реалізація безпечного запуску, автоматичного сну (`suspend`), рециркуляції аудіо-вузлів та захисту від навантаження ОЗП.
2. **Етап 2: Диспетчер клавіш та унікальний хеш (Key-Hash Engine)**
   - Реалізація `KeyHashDispatcher.ts` з підтримкою різних мов, символів та функціональних клавіш.
   - Створення вшитих пресетів (`cherry-blue`, `vintage-typewriter`, `deep-thock`, `cyber-neon`, `bubble-drop`).
3. **Етап 3: Інтеграція подій введення (Desktop Keyboard + Mobile Touch/IME)**
   - Створення хука `useTypingSound.ts`.
   - Підключення до фізичних подій клавіатури та мобільних `beforeinput` подій редактора.
4. **Етап 4: UI керування в панелі (Header Icon & Quick Menu)**
   - Додавання кнопки швидкого перемикання (`VolumeX` / `Volume2`) у хедер.
   - Спливаюче міні-меню гучності та швидкої зміни пресету.
5. **Етап 5: Менеджер пресетів, Обрані ⭐ та Імпорт JSON-файлів**
   - Діалогове вікно керування пресетами, фільтр обраних, кнопка завантаження зовнішнього файлу пресету.
   - Збереження в `localStorage` та перевірка валідності вхідних даних.
6. **Етап 6: Тестування та оптимізація**
   - Перевірка відсутності втрат пам'яті (Memory Leaks) при швидкому безперервному наборі тексту.
   - Перевірка роботи на мобільних пристроях у браузерах Safari / Chrome та WebView.
