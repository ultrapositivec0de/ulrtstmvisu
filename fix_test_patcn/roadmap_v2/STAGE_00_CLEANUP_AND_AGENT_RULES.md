## Покроковий план дій

- [ ] **Крок 0.1 — Перевірка уніфікованих правил у `AGENTS.md`**:
  - Переконатися, що правила щодо орієнтовного порогу 350–400 рядків на модуль (із винятками для словників, цілісних парсерів і рушіїв), доменної структури директорій, заборони резервних копій у `src/` та семантичних CSS-токенів актуальні.
- [ ] **Крок 0.2 — Верифікація відсутності активних імпортів**:
  - Виконати пошук по всьому репозиторію (`src/`, `scripts/`, `vite.config.ts`, `tsconfig.json`) на наявність згадок `.bak`, `backup_pre_refactor`, `step2`, `step3`, `src/chunks`.
  - Додатково перевірити, чи жоден скрипт у `package.json` або `.github/workflows/` не посилається на ці файли.
- [ ] **Крок 0.3 — Архівне збереження (за потреби) або видалення з `src/`**:
  - Оскільки історія зберігається в Git, безпечно видалити перелічені 17 залишкових файлів із `src/` (і порожню теку `src/chunks/`).
- [ ] **Крок 0.4 — Перевірка `.gitignore` та ESLint**:
  - Додати шаблони `*.bak`, `*.backup_*`, `*.step*.bak` до `.gitignore`, щоб запобігти випадковому повторному потраплянню резервних файлів до `src/`.
- [ ] **Крок 0.5 — Фінальна валідація**:
  - Запустити `npm run lint`, `npm run build`, `npm run check:tauri`.
  - Перевірити лічильник рядків `src/` (очікуване скорочення обсягу з ~93.4k до ~56.6k рядків).
